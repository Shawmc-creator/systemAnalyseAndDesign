# 青禾牙科诊所管理系统｜Figma设计提示词

依据：2026-10-18定稿需求文档B部分32个用例、D3岗位导航及10组页面线框。下方“主提示词”可整体提交给Figma Make。设计结果需经业务与版式核对后用于前端实现。

## 主提示词

你是一位有医疗机构业务系统经验的资深产品设计师。请为“青禾牙科诊所管理系统”设计一套专业、统一、可交互的中文Web工作台。

请主导视觉、信息层级、页面构图和组件设计。产品服务一家6名工作人员的小型牙科诊所：负责人兼牙医、另一名牙医、前台、收费人员及两名诊疗助理。主要使用场景是工作人员在接诊过程中反复查询、录入、核对和交接。

### 1. 产品目标及约束

- 全部面向工作人员，使用简体中文。患者的预约、资料和费用由工作人员办理；无需患者自助登录、患者商城或线上营销页面。
- 五个岗位：前台、牙医、收费人员、诊疗助理、负责人。负责人兼任牙医时，明确切换当前岗位，按当前岗位呈现操作。
- 高优先级是患者身份明确、当前就诊明确、下一步操作明确、办理结果明确，降低点错患者、看错日期、重复提交及混淆款项的概率。
- 普通工作人员不接触数据库表名、API、技术版本号等开发信息。涉及业务版本或签署时，提供“当前版本”“签署时间”等可理解的信息。
- 不增加医保结算、保险理赔、连锁多院区、会员营销、AI诊断、在线支付通道等未确认业务。
- 使用虚构患者和明确标记的示例数据。设计稿里的处理结果是原型演示，真实系统对接由后续开发完成。

### 2. 视觉与组件要求

请先建立适合中文医疗业务工作台的设计系统，再应用到页面：

- 气质：专业、清晰、可靠，具有牙科诊所自己的视觉识别；日常长时间使用舒适。
- 主界面以浅色为主。由你选择完整且协调的品牌色、背景、文字和语义状态色，保证对比度。正常、待处理、风险、完成的状态同时使用文字，避免仅靠颜色识别。
- 优先选择适合中文界面的字体，正文、表单、表格和辅助文字都应易读。按钮文字应简短且准确。
- 以1440px桌面布局为主，适配1280px笔记本，重点流程补充390px手机稿。小屏表单采用单列，表格可以在独立区域横向浏览。
- 使用统一网格、间距、字号、行高、圆角及控件高度；注重表头、列宽、金额、小数点、标签和操作栏对齐。
- 建立可复用的按钮、输入框、日期/时段选择器、搜索及患者候选项、表格、状态标签、导航、页签、抽屉、对话框、确认提示、错误提示、空状态、加载状态和业务凭证组件。
- 主次操作有明确层级。取消预约、停诊、签署、退款等操作应有对象、后果及依据核对，避免危险操作与普通按钮混淆。
- 如果使用Figma Design，使用可编辑文字、组件实例、Auto Layout、样式和变量；交付可继续维护的图层。如果使用Figma Make，输出可交互的高保真界面原型。

### 3. 信息架构及岗位职责

请设计稳定的应用外壳：品牌、当前岗位、当前日期、工作区域、个人菜单和退出入口。导航按岗位裁剪，只展示有权办理的功能。

| 岗位 | 工作区域 |
|---|---|
| 前台 | 预约与到诊、患者资料、复诊随访联系 |
| 牙医 | 诊疗工作台、健康资料、方案与文书、复诊随访评估 |
| 收费人员 | 价目、账单与付款、费用申请、退款办理、收支核对 |
| 诊疗助理 | 材料及批次库存、采购验收、器械处理与使用 |
| 负责人 | 日期排班、经营与资金明细、价目及费用审核、采购授权、账号与运行管理 |

患者、预约、就诊、方案、账目、付款和退款均有独立业务编号。页面衔接时保留同一患者和来源关系，不能让使用者以为这些编号表示同一件业务。

### 4. 第一轮请优先交付的界面

第一轮围绕实际使用设计以下页面及关键弹层，形成一个统一的设计方案，不必一次填满全部业务页面。

**A. 工作人员登录**

个人账号、密码、登录状态、失败反馈。进入对应岗位工作台。产品介绍保持简洁，突出工作入口。

**B. 前台预约与到诊工作台**

- 提供今日/指定日期、牙医、诊椅、预约状态筛选，以及新增预约、患者候选查找和现场到诊入口。
- 设计直观的按时间与牙医/诊椅查看安排的方式，并提供便于查找和办理的列表。由你决定时间视图和列表的主次结构。
- 显示时段、患者姓名及患者号、接诊牙医、诊椅、就诊目的、预约状态和可用操作。
- 单独呈现今日已到诊患者及其候诊/接诊情况，避免把“预约状态”与“就诊状态”混在一起。
- 弹层：新增预约、改约、取消、人工核实未到、记录实际通知、登记现场到诊。
- 同名患者候选示例：“陈晨 / P001 / 电话尾号0001”和“陈晨 / P002 / 电话尾号0002”；必须主动核对选择，不能自动合并或默认确定身份。
- 排班示例：周医生/一号诊椅，09:00—12:00；陈晨09:30—10:00口腔检查；李然10:30—11:00复查；另一位牙医/二号诊椅有不同安排。
- 预约状态仅为：已预约、已取消、已到诊、未到。就诊状态为：候诊、接诊中、诊疗结束。日期过去不会自动判定未到；明日预约不能登记为今日到诊。
- 患者、牙医或诊椅冲突时，显示冲突对象与可改选时段。改约失败仍保留原预约，不能显示改约成功。
- 到诊成功展示就诊号和候诊结果，允许衔接牙医工作台；到诊不表示已经完成治疗。

**C. 患者资料及身份核对**

- 搜索姓名、电话、完整患者号；候选列表明确区分同名患者。
- 表单包括姓名、出生日期（未知可空）、联系电话、电话归属、无可用联系方式原因、联系偏好及地址。
- 修改需要填写原因，并能查看对应原值、修改记录及操作时间。
- 代理办理包括代理人、关系、可代办范围、有效期间及核实依据。
- 患者页面按岗位控制临床资料的访问，前台资料维护页面不提供修改诊断的入口。

**D. 负责人日期排班**

- 按指定日期核对牙医、诊椅和起止时段，发布或调整已确认安排。
- 同时检查人员与诊椅的可用性。停诊只作用于指定安排。
- 调整/停诊弹层需填写原因，并显示受影响的预约、待联系和办理进度；存在未处理占用时清楚提示后续责任。
- 提供正常空档、资源冲突、已有预约受影响三种示例状态。

**E. 牙医诊疗工作台**

- 左侧或合适区域展示当日候诊/接诊患者；临床工作区域固定显示当前患者、患者号、就诊号、责任牙医和状态。
- 包含病历草稿、健康复核、检查所见与牙位、诊断及处理意见、实际执行项目、既往资料和签署核对。
- 健康信息区分“未知”“已询问有记录”“无相关情况”；未知不能默认显示为无过敏。
- 持续方案展示版本、计划项目与牙位、数量、患者决定及文书依据。预计费用与实际执行收费分开。
- 签署前有完整核对；签署后原正文只读，后续通过独立补充记录保留作者及时间。

**F. 收费与退费工作台**

- 区分应收、已分配付款、未付、未分配原款、可用预付款和待核实退款占用。
- 样例数字必须自洽：应收1000元；原收款500元；其中300元分配到账目；账目未付700元；未分配原款200元；这200元正在被待核实退款占用，因此可用原款为0元。
- 提供费用明细、计价依据、付款分配、费用申请及退款办理记录；现金交入、实际收款和找零分别表达。
- 付款状态：待核实、到账已确认、未到账已核实。
- 退款状态：待办理、待核实、已确认退款、已失败。结果未知时提供核实原办理入口，不能鼓励重新支付或重新退款。
- 费用调整先申请、负责人审核，再按获准范围办理，保持角色分工。

**G. 复诊随访工作台**

- 由牙医提出带诊疗来源的复诊/随访要求，前台查看待联系列表并追加联系结果。
- 展示患者、来源就诊/方案、目标日期范围、事项、负责前台、联系经历、下一联系日期和关联复诊预约。
- 复诊随访状态：待发布、待联系、待到诊或评估、已完成、已撤销。
- 示例包含未联系上且已有下次联系日期、已安排复诊待到诊、等待牙医评估。前台完成联系不等于临床评估已完成。

### 5. 后续页面的导航位置与业务边界

第一轮同时为以下区域规划导航位置和共用组件；后续轮次再逐一展开其高保真页面：

- 方案与文书：持续治疗方案版本、项目范围、患者决定、影像及文书原件/版本。
- 材料库存：材料、批次、效期、可用/隔离状态、入库、领用、盘点、原始流水。
- 采购与供货：供应商、采购安排、验收和退换、付款、结算分配及原单追溯。
- 器械处理：处理记录、核对放行、器械包次、发放/使用确认及异常追溯。追溯不能自动跨越临床访问权限。
- 经营与运行管理：业务明细、实际资金明细、收支核对与差异处理、岗位资格与账号授权、审计、备份及隔离恢复核验。

### 6. 全局交互与状态

- 关键页面提供正常、空数据、查无候选、加载、保存中、保存失败、冲突及权限不足状态。
- 同一次办理重复点击返回原结果。处理中抑制重复提交，结果未知保留原提交信息并提供核实入口。
- 资料已经被其他工作人员更新时，显示刷新与重新核对入口，保护用户尚未提交的输入。
- 失败时保持上下文及已填字段；可恢复问题要明确指出字段或冲突对象。
- 敏感步骤要展示当前患者、当前就诊或原资金凭据。金额统一人民币两位小数并右对齐，日期使用诊所当地时间。
- 高频操作支持键盘焦点、清晰字段标签和可见的必填/可选说明。小屏仍能找到退出及主要办理入口。

### 7. 交付与设计自检

请先给出简短的设计方向与信息架构说明，然后制作第一轮完整高保真页面和可点击主流程：负责人确认日期排班→前台核对患者→预约→改约→到诊→牙医接诊。费用、随访页面提供各自连贯的示例流程。

同时提供可复用组件及其正常/禁用/错误等必要状态；补充预约表单、患者选择和手机工作台稿。请主动检查长中文、同名患者、较长编号、空列表和错误消息，修正文本截断、错列、重叠、留白失衡及金额矛盾。

完成后请说明各页面入口、主流程如何点击，以及哪些业务尚属下一轮设计。实现必须遵守上述岗位和业务规则。
