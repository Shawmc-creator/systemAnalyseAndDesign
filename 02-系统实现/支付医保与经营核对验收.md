# 支付、医保与经营核对验收

日期：2026-10-21。按现行179页需求文档补齐UC-21、UC-22、UC-23，以及UC-13/14的电子支付、医保退补衔接。需求PDF、LaTeX、69表核心模型及原设计SQL未修改。

## 本轮完成

| 业务 | 网页与后端办理 |
|---|---|
| 电子支付 | 从原账单建立唯一业务单；核查同一原单的处理中、未知、成功、失败、关闭结果；成功后一次登记患者原款及用途，未知不增加到账或允许重复收费 |
| 医保身份与费用 | 核实机构启用条件；前台核验身份、登记就诊；收费核对已签署诊断、全部实际费用、地区编码及有效期，保存官方预结算与患者真实选择 |
| 正式医保 | 使用原办理号记录提交、回查未知结果、核实正式分摊；费用等于基金、个账及患者其他自付之和，预估不代替最终结果 |
| 原单撤销与退补 | 负责人按同账单的费用申请核实撤销范围；收费核查原撤销号，未知保留原分摊；成功后保留原结算，重新核对最终费用及患者实际退款 |
| 医保结算款 | 原结算关联分批实际拨付和撤销后的实际退回，唯一凭据和原额度校验；待回款不计患者现金实收 |
| 日常经营 | 按日期分别显示接诊、实际项目、总费用、患者待付、实收实退、医保承担及实际收付；全部医保待收付单独显示 |
| 日终与差异 | 原收退款生成不可覆盖的日终快照；现金含期初及移交；逐笔渠道差异另留核对记录，负责人明确责任人、日期并记录进展和完成依据 |

各操作重新校验岗位、授权、原记录版本及提交号；重复提交返回原回执。医保正式结果或原电子支付未明确时，禁止改动原费用或重复办理患者退补。已移出的复杂供货资金等功能未恢复。

## 真实联网边界

**当前没有连接微信、支付宝、银行或地区医保生产接口。** 电子支付与医保采用人工核实官方终端原单的方式；系统不自动扣款、不生成支付二维码、不发送医保正式请求，也不把演示结果称为真实平台响应。

实际运行库的医保条件、院内药学条件均未启用。本轮没有授予真实药学资格，没有将医保、电子支付或发药演示事实写入运行库。医保机构配置示例在`app/config/insurance-config.example.json`；部署人员核实定点及办理条件后，填写`app/data/insurance-config.json`并重启，才能开放人工核实办理。人员资格与机构条件分别核对。

自动联网仍需具体支付商户与当地医保接入资料、正式接口适配及联调；这部分不能通过演示或填写配置伪装完成。实际待遇、目录、撤销规则以当地平台核实结果为准。

## 演示

1. 双击作业根目录的`05-体验支付医保演示.cmd`，打开`http://127.0.0.1:3002/`。这是独立内存程序，关闭进程后重置。正常运行入口仍为3001。
2. 账号为`frontdesk`、`cashier`、`manager`，密码`Clinic123!`。演示时钟固定在2026-10-19 09:35，已准备600元实际费用、虚构身份和编码。
3. 收费人员进入“医保办理”，核对费用和预结算。演示可填基金350元、个账50元、患者其他200元；预结算有效截止填2026-10-19 11:35。编码、待遇和诊断均为流程演示内容。
4. 记录患者医保选择，按同一原号保存正式提交，先试“仍待核实”，再核实成功。账单仅剩患者200元待付。
5. “收费与退费”核对患者及账单，建立200元电子原单；“经营与收付核对”查询原支付，未知不记到账，成功后一次分配患者款。
6. 医保实际拨付100元后，患者实收仍为200元，医保实际收100元、待回款300元。日终结单差异、责任安排及撤销流程可继续办理。

命令行演示：在`app`中执行`../runtime/node.exe scripts/demo-v2-settlements.js`；全流程网页验收脚本为`scripts/check-v2-settlements-ui.cjs`，需本机Playwright及Chrome，仅用于验证。
