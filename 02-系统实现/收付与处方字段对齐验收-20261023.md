# 收付与处方字段对齐验收

依据现行164页、144图需求文档，本轮落实UC-13、UC-21、UC-25及基础材料采购相关字段与流程。需求PDF、LaTeX、77表986字段模型和原始SQL未修改。

## 已完成

| 文档业务 | 代码及页面结果 |
| --- | --- |
| 电子预收 | `payment_order.patient_funds_id`明确患者归属，`bill_id`可空；无账单直接建立预收原单。未知不计到账；核实成功共同保存唯一原付款和预付，日后抵扣不再新增收款 |
| 现金逐笔核对 | `payment_reconciliation.patient_payment_id`引用现金原款，与电子支付/退款恰选其一；处理另增记录，保留原营业日和原金额。部分成功退款按实退额核对 |
| 处方草稿及交付 | 用药指导草稿可空，开立前必须补全；下载不等于交付，牙医明确记录实际文件交付人和时刻。院外药品领取不据此推定，不形成诊所出库及药费 |
| 作废与重开 | 未核实药品尚未交付时拒绝直接作废；有据作废保留实际牙医和原文件交付。重开引用同患者同就诊原方，并重新明确药品、数量、用法及指导；原方、签署摘要和原发药保留 |
| 分类与采购 | 材料类别由既有`is_drug`生成“材料/药品”，不维护两套可冲突分类；采购取消单独保留`cancellation_reason`，不覆盖原需求 |
| 结构盘点 | 改用`PRAGMA table_xinfo`；净额`net_cents`本来就是非空生成列，旧盘点漏读，本次纠正该误报，没有重复增加净额列 |

新增7个关联或依据列及1个生成分类列，均来自现行模型。重建电子支付、逐笔核对和处方三张表以调整可空约束；原主键、原列、索引、原签署摘要及已分配编号上限保持。新交付和作废人员不由旧记录推定，旧未知事实不补造。
