# 工作人员网页与业务办理

系统地址：`http://127.0.0.1:3000/`。各岗位登录后显示相应菜单，后端也校验角色。

| 岗位 | 页面与办理职责 |
|---|---|
| 前台 | 患者资料、预约和直接调整、当日到诊、诊后联系及复诊预约关联 |
| 牙医 | 本次患者检查和病历、方案沟通及患者决定、实际项目确认、签署补充与项目更正、提出随访要求并评估结果 |
| 收费人员 | 待结算费用、确认价目及区间、现金实收和找零、查询原收据、日常现金核对 |
| 诊疗助理 | 诊前协作安排、材料库存及流水查询、入库领用和记录负责人确认的盘点调整；无临床正文入口 |
| 负责人 | 员工与接诊安排、项目基础资料、价目和库存查看、同期间业务与收款统计；兼任牙医时办理本人诊疗 |

## 典型演示

1. `frontdesk`在预约页查询已确认接诊时段，勾选牙医已确认事实，建立预约。调整须说明原因；到诊仅办理当日预约，重复登记返回原就诊。
2. `dentist`在诊疗页打开本人的就诊，填写病史、牙位、检查与诊断，说明方案并记录患者决定；确认实际完成的项目，最后签署。其他牙医及助理不能代签。
3. `cashier`打开“待结算示例”，核对项目及应收，输入现金实收，查看找零。已结清“现金找零示例”提供原收据。
4. `cashier`在价目页依据负责人确认记录维护新价目，可以同时结束原版本；不得覆盖已使用的历史区间。
5. `dentist`提出有病历来源的诊后要求，`frontdesk`登记联系反馈、未接通的下次日期或关联复诊预约；牙医在复诊病历确认后记录评估。
6. `assistant`或`assistant2`在材料页登记入库、实际领用或已由负责人确认的盘点差异。超过库存不能领用。
7. `cashier`在核对页核对当日实际现金净收，填写差异和处理意见；`manager`查看同期间的就诊、项目及现金收款。

页面中的数量、实收、找零、确认时间和原始凭据都由接口处理并保存；前端隐藏按钮不能替代后端权限。旧患者网页仅用于联系前台说明。

## 新版办理要点（2026年10月7日）

- 前台在患者档案中点“修改资料”，填写变更原因；保存后能查看原值与经办历史。过期页面须重新查询。
- 前台在预约页按日期、患者姓名或电话检索；牙医在可用时段入口查询本人接诊安排。
- 牙医在现有方案旁点“记录患者决定”，区分待考虑、同意、拒绝和暂缓。签署须完整填写主诉、牙位检查、诊断、诊疗经过及诊后指导。
- 诊后要求选择复诊或随访。前台填写实际联系时间及反馈，未接通须填写下次日期；需要复诊时先建立预约，再选同患者有效预约关联。牙医记录恢复情况、评估结论及后续意见。
- 负责人发布每周接诊安排时填写原因、接诊牙医实际确认时间和意见。仍有预约失去覆盖时先处理预约。
- 助理查询材料时区分当前余额和所选期间流水。盘点调整按负责人实际确认内容填写确认人、时间和意见。
- 收费人员查询原结算依据后核对现金净收；有差异时填原因、处理意见及负责人确认。收款集合变化会拒绝旧依据，重新查询后再核对。
- 同一个办理窗口的原内容重试返回已保存结果；已经成功后改变内容，要先查原记录，再重新打开窗口办理。
