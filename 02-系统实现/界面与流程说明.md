适用版本：20261022，现行需求文档25个用例。正常系统为`http://127.0.0.1:3001/`，支付医保隔离演示为`http://127.0.0.1:3002/`。

## 一、拿到文件夹后先做什么

1. 双击作业根目录的`06-检查交付环境.cmd`。检查当前前后端、网页资源、需求PDF和LaTeX、启动文件及数据库隔离初始化；不修改运行数据。附带便携Node.js，GitHub源码包需自行安装Node.js 24以上版本。
2. 双击`01-一键启动系统.cmd`，浏览器进入3001。不要直接用文件方式打开工作台，正常业务需要后端服务。
3. 通过岗位演示账号登录。密码均为`Clinic123!`；下列账号仅用于作业中的虚构数据演示。

| 岗位 | 账号 | 主要页面 |
|---|---|---|
| 前台 | `frontdesk` | 患者资料、预约与到诊、复诊随访、资源、医保身份登记 |
| 牙医 | `dentist` | 牙医接诊、影像文书、处方、复诊评估、资源 |
| 收费人员 | `cashier` | 收费价目、收费与退费、医保办理、经营与收付核对 |
| 诊疗助理 | `assistant`、`assistant2` | 影像上传、材料采购库存、资源准备 |
| 负责人兼牙医 | `manager` | 排班、价目核对、费用审核、采购库存、资源、经营核对、医保管理；切换牙医岗位办理本人诊疗 |
| 药学岗位 | 负责人核实并授权的个人账号 | 条件具备后可选择药学岗位，办理审方与实际发药，不自动由助理代行 |

正常库的医保、院内药学条件尚未启用。需要展示医保时使用独立3002演示；真实支付及医保生产平台未联网，系统采用人工核实官方终端原单的方式，不自动扣款、生成支付码或发送正式医保请求。

## 二、正常诊所业务怎么演示

| 顺序 | 岗位与办理 | 要看到的结果 |
|---|---|---|
| 1. 开诊安排 | 负责人按当日确认牙医、诊椅及接诊时段；助理核实清洁、器械及必要设备 | 资源满足条件才能安排接诊，停用或占用会阻止冲突操作 |
| 2. 预约到诊 | 前台核对患者号与联系电话，建立预约；患者实际到院后登记到诊 | 同一患者和同一资源不能重叠预约；到诊进入候诊并建立病历草稿 |
| 3. 检查诊疗 | 牙医打开本人就诊，复核健康资料、检查诊断，说明方案和费用并记录患者决定 | 有患者决定及实际业务依据，实际执行与方案预计分别保存 |
| 4. 文书处方 | 助理上传原件，牙医核实归属；牙医开立处方、明确用药指导和院内外路径 | 原件版本可下载；处方开立不提前扣库存、不提前生成药费 |
| 5. 实际收费 | 收费核对实际项目及价目，按患者承担额收款；未知结果保留原单核实 | 预计费用不变成应收；到账、用途分配和预付款分开，确认只记一次 |
| 6. 诊后交接 | 牙医签署并交代复诊要求，实际结束使用后交助理清洁准备；前台联系并关联预约 | 病历结束、资源恢复、费用结清分别有状态；需要临床评估的随访交回牙医 |
| 7. 日常保障 | 助理登记采购、验收、实际领用和盘点；负责人核实差异和放行 | 库存以合格到货及实际出入为准，不能负库存或无据调整 |
| 8. 日终核对 | 收费核对原收退款及实际结单，负责人查看经营、欠费和医保待回款并安排差异责任 | 费用、患者实际收付、医保承担和实际回款分列，不直接改统计合计 |

修改原记录前先刷新；同一提交响应丢失时使用“核实上次提交”，不重复办理。费用更正、医保撤销和实际退款分别保留原单与结果。

## 三、支付医保完整示例

双击`05-体验支付医保演示.cmd`进入3002。该程序只使用内存，固定演示时间为**2026-10-19 09:35**，关闭进程后重置；不会写入3001运行库。已准备600元实际费用、虚构身份及项目编码，金额和编码仅用于流程说明。

1. `cashier`进入“医保办理”，打开原办理的“核对费用与预结算”，选择该患者账单、身份及演示编码。演示诊断编码可填`DEMO-DIAGNOSIS`；基金填350元、个账50元、患者其他自付200元。预结算号填`DEMO-PRE-1`，有效截止填2026-10-19 11:35，填写演示核对依据。
2. “说明并记录患者选择”选择医保；再用同一业务号登记正式提交。在“查询核实正式原单”先保存“仍待核实”，查看没有新增医保成功及现金实收。
3. 再核实成功，正式结算号填`DEMO-SETTLE-1`，确认患者、机构及费用一致。正式结果保存后，患者只剩200元待付。
4. “收费与退费”核对该患者账单，建立200元微信电子原单；“经营与收付核对”查询同一原支付，先保存未知，再核实成功。成功时填写演示交易号`DEMO-PAY-1`并核对收款方，患者实际收200元只记一次。
5. 返回医保页面，实际拨付填100元、凭据`DEMO-BANK-1`。经营页面应显示患者实收200元、医保实际收100元、医保待回款300元，不能显示为患者实收300元。
6. 收费可按微信读取原款快照，填写实际结单199元，保留1元差异；负责人回查原渠道单、安排责任人及处理日期，再保存实际处理结果。差异处理不改患者原收200元。
7. 展示撤销时，收费先按原账目和原款提交费用申请，负责人核实同一申请的医保撤销范围，收费回查原撤销号。未知保留原分摊；成功后保留原正式结算及撤销记录，医保已收款的实际退回另记。
8. 医保撤销改变了原账目状态，负责人将原费用申请退回重核，收费重新核对后提交；负责人确认费用调整和原用途释放，再由收费建立并核实患者实际退款。仅退患者原自付款，不把医保承担额当作患者可退现金。

完整网页自动验收脚本在`app/scripts/check-v2-settlements-ui.cjs`，包含上述流程及患者实际退款，使用隔离库和本机Playwright/Chrome。命令行演示为`npm run demo:settlements:v2`。

## 四、当前数据备份

在`02-系统实现/app`目录执行：

```powershell
../runtime/node.exe scripts/backup-v2.js
../runtime/node.exe scripts/verify-backup-v2.js
# 已安装Node.js时也可使用 npm run backup 和 npm run verify:backup
```

备份包在`app/data/backups/clinic-v2-bundle-*/`，包含SQLite一致性快照、该快照引用的全部文书原件、已有机构配置及摘要清单。原件缺失或摘要不符时标记失败，不报告完成。校验命令默认检查最近完成包，也可传入指定备份目录。

恢复时先将完整备份包复制到独立恢复目录，由管理员核验副本后安排切换；不要直接在唯一备份包内运行系统。此次验收只打开隔离恢复副本，没有覆盖运行库。运行数据及机构配置不上传GitHub。
