# 课程总结版诊疗代码对齐与验收

日期：2026-10-23。基准为164页需求文档、现行25个用例及77表设计。本批落实UC-06、07、08、09、24的主要差异，同时回归现有系统；完整代码与设计的对齐仍在进行。

## 1. 已落实的业务

| 需求 | 后端与数据库 | 网页操作 |
| --- | --- | --- |
| UC-06：未完成内容可暂存 | 草稿允许诊断、处理意见和所见暂缺；仅签署时要求完整；保存仍比对版本、归属和权限 | 可先记主诉保存，不生成虚假的所见或诊断；实际结束后的未签草稿仍可补全 |
| UC-09：签署不替代实际结束 | 签署只固定正文、所见及`signed_health_review_id`，不写就诊结束，不释放资源 | 明示采用的确切健康复核及完整性结果；签后正文只读，补充单独办理 |
| UC-24：牙医确认真实结束 | 实际结束、诊椅和设备释放、清洁准备限制共同提交；就诊保存真实`ended_at`和结束状态 | 牙医单独确认结束；助理完成清洁核查后再恢复，未核验前保持限制 |
| UC-07：明确项目和数量 | 连接表增加`scope_quantity`，明确整项或限定数量，不能将遗漏自动当作整项同意；既有决定不覆盖 | 每个选中项目须选择整项或限定数量；展示计划、已完成、有效同意上限和余量 |
| UC-08：不得超过同意范围 | 新同意替换当前适用上限，不累加历次同意；部分撤回扣除未执行范围，保留已完成事实；实际执行和更正均核对数量 | 超额执行拒绝且不生成费用；保留输入供补正；部分撤回后仍可选择合法余量 |
| UC-07：按有效范围核对完成 | 已同意数量完成且没有未决定或暂缓项目时，才确认本版完成；不强迫执行已明确拒绝的项目 | 显示实际决定和余量，原方案、原决定及实际执行继续可查 |

同意的限定数量按当前项目累计执行上限解释，撤回数量按撤回的未执行量解释。实际记录更正保留原记录和原应收，费用变化继续通过费用申请办理。没有增加供货结算、器械逐包追溯或其他已删除的边缘功能。
