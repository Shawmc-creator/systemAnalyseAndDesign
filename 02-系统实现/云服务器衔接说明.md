# 云服务器衔接说明

## 当前课程试用

虚构数据演示已在腾讯云 Windows Server 运行。Caddy 使用私有 CA 为公网 IP 提供 HTTPS 和试用认证，再转发至本机 `127.0.0.1:3011`。试用者按[在线演示说明](../README.md#在线演示)访问。服务器上的 Caddy 配置、试用凭据、证书私钥及运行数据由部署者保管。

下述正式部署准备面向实际门店运行。应用和持久化数据库可先集中部署在一台服务器，由各门店通过浏览器接入。正式连锁数据库和外部业务接入须按实际数据和机构条件核实。

## 现有入口与数据

- `3011` 是固定日期虚构演示：它使用演示快照和演示账号，启动脚本只监听本机。不能当作正式连锁数据库或直接放到公网。
- `3021` 是连锁开发工作副本：数据库和文书原件保存在独立目录，支持部分连锁业务及重启保存，但仍带有候选库和开发副本标记，不能直接当作正式业务库。它同样仅允许本机 Host 与 Origin。
- 旧的单店业务库、候选库、工作副本和演示快照互不等同。不得直接用虚构数据覆盖真实数据，也不得跳过门店归属及人员权限核对。
- SQLite 可作为集中式单服务器的初期方案，但不能把同一个 SQLite 数据库文件放在共享盘供多台应用服务器直接写入。访问量、并发和可靠性要求确定后，再评估其他数据库；不能通过简单改连接字符串完成迁移。

## 上服务器前需要完成

1. 完成正式连锁运行入口：使用实际时间和经审核的正式数据库，补齐主要业务及身份会话接线；迁移真实历史数据时先备份并核对各记录门店归属和人员权限。
2. 按实际域名实现受控的 Host / Origin 检查与 HTTPS 会话设置。现有 `127.0.0.1` 限制不能简单删掉；登录密码、会话管理、权限、访问日志和患者身份核验要适用于远程访问，演示账号不能用于正式环境。
3. 应用监听服务器本地地址，通过反向代理提供 HTTPS；按最终部署方式配置服务自启动、异常重启、健康检查和日志。实际网络访问范围由诊所确定。
4. 把数据库、影像文书原件和必要配置放在独立持久目录，代码更新不能覆盖数据。建立定期备份、异地保存、恢复演练及访问权限；备份和日志均须保护患者信息。
5. 在隔离环境用虚构患者核对门店隔离、主要流程、备份恢复和重启，再按真实机构条件处理身份服务、医保及相关部署要求。系统只登记已核实的系统外支付结果，不发起真实支付。

## Windows 演示包准备

在 `app` 目录执行 `node scripts/prepare-windows-demo-package.js <作业目录之外尚不存在的输出目录绝对路径>`，可以生成独立的 Windows 本机演示包。包内包含演示程序和初始化结构，不包含现有数据库、影像原件、患者资料及 Node.js 运行环境。安装 Node.js 24 或以上版本后，可双击包中的启动文件生成新的虚构演示数据。

演示后端仍仅监听本机。为将来让其他人查看虚构演示，包内提供 `02-系统实现/app/cloud/Caddyfile.example` 反向代理样例；域名、访问密码及 HTTPS 必须配置完成后才可开放，不能直接开放 3011 或 3019 端口。此路径仅用于虚构数据，不是正式诊疗入口。

准备好腾讯云 Windows 服务器和符合使用条件的域名后，按下列顺序配置：

1. 安装 Node.js 24 或以上版本及 Caddy，将演示包放到独立目录；确认服务器的 3011 端口未被其他程序占用。
2. 将域名解析到服务器，按适用要求办理备案。参考 Caddy 官方 HTTPS 指引放通 80 和 443，远程桌面端口按需要限制来源；不要对公网开放 3011、3019。
3. 在服务器运行 `caddy hash-password`，交互式输入另行设定的访问密码，将输出的哈希及实际域名填入 `Caddyfile.example` 的副本。访问密码与演示岗位密码不同，配置文件不提交 GitHub。
4. 在 PowerShell 中设置 `$env:CHAIN_DEMO_PUBLIC_ORIGIN='https://你的实际域名'`，然后在同一窗口运行包中的 `07-启动连锁演示.cmd --no-browser`。该值必须与浏览器访问时的 HTTPS 来源完全一致；如演示已在未设置来源时运行，应先停止旧服务再启动。
5. 使用 `caddy validate --config <配置文件>` 校验配置，再运行 `caddy run --config <配置文件>`。浏览器访问 HTTPS 域名时先输入访问密码，再登录演示岗位账号。需要设置后台持续运行、定期备份并用另一台设备核对访问。

同一 PowerShell 窗口中可运行 `node 02-系统实现/app/scripts/check-cloud-demo.js <Caddyfile绝对路径>` 检查 Node.js、来源、代理配置及本机演示服务；检查通过也不代表 HTTPS 证书和外部访问已经验证。请勿将填入密码哈希的配置文件提交 GitHub。

本机已使用 Caddy 2.11.9 和虚构数据验证代理配置、HTTPS、登录及来源检查。腾讯云当前试用入口以私有证书运行，已从外部验证证书和认证提示，并由项目提交人在浏览器确认进入网页。正式域名、公信证书及长期运行安排待落实。

## 当前可用的开发副本备份

使用 Node.js 24 或以上版本，在 `app` 目录执行，备份目录需事先创建，且与工作副本目录分离：

```text
node scripts/backup-chain-workspace.js <工作副本绝对目录> <已有备份目录>
node scripts/backup-chain-workspace.js --verify <生成的备份包绝对目录>
node scripts/backup-chain-workspace.js --restore <备份包绝对目录> <不存在的新目录>
```

程序使用 SQLite 备份接口复制数据库，再按数据库记录复制并校验对应的影像文书原件和清单；备份不完整会标记失败，不会覆盖原数据。恢复仅创建新目录并重新校验，不覆盖已有工作副本，可用于隔离环境演练。该工具针对带标记的开发工作副本，不是正式库迁移或恢复工具。备份包含敏感资料，应限制访问，禁止提交 GitHub。
