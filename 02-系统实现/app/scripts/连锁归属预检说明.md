# 连锁历史归属预检

`check-chain-assignments.js` 对指定 SQLite 数据库进行只读检查，核对候选清单中直接添加门店字段的旧表。它检查数据库完整性与外键、映射是否覆盖每条旧记录、字段是否齐全、门店编号是否属于提供的门店清单，以及是否存在多余记录。

使用前应先通过现有备份功能建立一致性备份，并使用隔离副本。三个输入都须明确提供：

```text
node scripts/check-chain-assignments.js <隔离数据库副本> <连锁业务表归属候选映射.json> <人工核实的门店映射.json>
```

映射格式示意（编号均为虚构）：

```json
{
  "branchIds": [1, 2, 3],
  "tables": {
    "appointment": {"101": {"branch_id": 1}},
    "followup_requirement": {"201": {"source_branch_id": 1, "responsible_branch_id": 2}}
  }
}
```

实际输入必须覆盖候选清单要求的所有直接归属表中的所有记录。候选表及字段须使用合法名称，重复字段、继承而非明确提供的记录或字段不会通过核对。`assignmentComplete` 仅表示这部分映射形式完整，不能证明门店归属真实，也不意味着可迁移；继承归属、健康资料来源、运行支撑表、业务约束、触发器和附件等仍须另行核对。患者登记来源不明可保持未知，不得据此开放跨店临床资料。输出只含表名和数量，不输出患者信息或记录编号；映射文件本身仍须妥善保管。工具不修改数据库、不自动迁移，未提供任何输入时不使用默认运行库。

隔离赋值试验与备份包核对还检查 22 项已明确的关联门店一致性，覆盖排班、预约、就诊、诊疗、文书、账单、收款登记、退款申请、医保、库存、采购及复诊来源。可选关联为空时不作为冲突；复诊按来源门店核对，不要求负责门店与来源门店相同。这些检查只能发现所列关联的归属缺失或冲突，不能证明历史归属真实，也不能代替患者身份、资金账户及全部业务关系的核验。

备份包核对及隔离赋值试验另外检查 8 项患者或资金账户关联：就诊与预约、文书与就诊、医保业务与就诊的患者，以及费用申请、退款、支付登记涉及的账单与收款账户。发现冲突或必要值缺失时，不能进入赋值试验；检查输出只列汇总数量。它不覆盖所有患者和资金关系，仍需结合历史凭证核验。

## 候选基础结构的快照试验

```text
node scripts/check-chain-snapshot-trial.js <已备份的隔离数据库快照>
```

该命令以只读方式读取快照，在内存副本中分别验证失败回滚和候选结构建立，对照旧表的原字段、记录摘要、显式索引、触发器、自增序列及数据库完整性。试验依据候选映射新增 29 个门店字段、四张连锁表和健康资料来源字段，并检查旧记录对应字段均保持未知；患者资金与材料批次的门店唯一约束也进行了内存重建和回滚试验。输出仅包含汇总数量和试验结果。它不向原文件写入，也不执行真实迁移；来源归属赋值、运行数据库的唯一约束重建、门店约束及旧触发器改造、门店授权配置和网页功能仍未完成。应先使用现有备份功能创建一致性快照，连同临床文件和配置一并保存。
