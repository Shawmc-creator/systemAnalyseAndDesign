# 诊椅设备与实际操作交接实施及验收

日期：2026-10-19。以现行179页需求文档为准，本批实现接诊资源基础流程，接入已有网页，不进行界面视觉改版。需求PDF、LaTeX和历史85表建表文件未改。

## 已完成

| 业务 | 岗位及处理 |
|---|---|
| 设备资料 | 负责人登记共享或固定诊椅设备，维护可用及停用状态；有预留或使用时不能直接改变固定诊椅 |
| 必要设备预留 | 前台在预约、改约及现场到诊时选择实际需要的设备；设备冲突与诊椅冲突一并拒绝，失败整体回滚 |
| 到诊和开始 | 预约后发生故障仍可记录患者真实到店；开始接诊时重新检查诊椅、牙医、必要设备和生效限制 |
| 实际延时 | 已开始的实际使用不因计划结束时间到达而消失，下一患者保持候诊，不能重复使用诊椅或共享设备 |
| 签署与交接分开 | 签署结束临床记录，保留未交接的实际资源；牙医另外确认实际操作结束，设备记录真实结束，诊椅转入清洁待核验 |
| 清洁及停用恢复 | 助理或负责人记录准备、故障及维护；核实实际使用结束、填写核验依据后解除。预计结束时间不会自动解除限制 |
| 记录可查 | 前台、牙医、助理和负责人可查资源状态、预留、实际使用和恢复记录；不返回病历正文及无关患者联系资料 |

实际操作结束可以在病历签署前或后确认。先交接资源不代表已经签署病历；后续实际项目的发生时间不能超过已确认的实际结束时间。取消的设备预留保留历史，不填写虚构的实际使用结束时间。

## 网页使用

启动新版服务后访问`http://127.0.0.1:3001/`，重新登录以取得新进程会话。

- 负责人：侧栏“诊椅与设备”，登记或维护设备、记录停用、核验恢复。
- 前台：“新增预约／改约／现场到诊”勾选本次必要设备；“诊椅与设备”只读核对状态及设备预留时段。
- 牙医：“诊椅与设备”对本人已开始的就诊确认实际操作结束。
- 助理：登录后进入资源页，记录准备／停用并完成实际恢复核验。

## 文档与接口对应

| 现行文档 | 接口或处理 |
|---|---|
| UC-02 预约 | 原`/api/v2/appointments/maintain`增加`equipmentIds`；改约不传该字段时保留原设备选择 |
| UC-03 到诊 | 原`/api/v2/visits/register`衔接设备预留；现场到诊可传`equipmentIds` |
| UC-06 接诊 | 原`/api/v2/clinical-records/record`的`start`增加真实资源检查 |
| UC-09 签署 | 原`/api/v2/clinical-record-signatures/sign`签署后不自动释放实际使用 |
| UC-24 资源协调 | `GET /api/v2/resources/query?date=YYYY-MM-DD` |
| UC-24 设备维护 | `POST /api/v2/resources/equipment` |
| UC-24 准备与恢复 | `POST /api/v2/resources/blocks`，动作`block/restore` |
| UC-24 实际操作结束 | `POST /api/v2/resources/finish` |

POST沿用登录Cookie、岗位、CSRF及`commandVersion:1,requestKey`。操作同一记录需提交查询所得版本；结果未知时保留原提交号核实。资源权限独立使用`resources.*`，不与旧32用例中的费用申请`uc24.*`混用。

`equipment`：`name,equipmentType,chairId,status,reason`；共享设备`chairId:null`。维护另带`equipmentId,expectedRevision`。

`block`：诊椅`chairId`或设备`equipmentId`择一，另填`startsAt,endsAt?,reason`。`endsAt`为预计时间。

`restore`：`blockId,expectedRevision,confirmed:true,verificationNote`。仍实际使用时拒绝恢复，其他生效限制也不会被连带解除。

`finish`：`visitId,expectedVisitRevision,expectedOccupancyRevision,endedAt,confirmed:true,reason`。须为原接诊牙医，或具有明确`physicalEnd`操作范围的有效临床交接；实际时间不能在未来或早于既有实际治疗。
