# 院外处方实现与验收

本文件记录上一批院外处方验收；当前院内外实现、数据库版本及检查数量见[院内药学与实际发药验收](院内药学与实际发药验收.md)。

日期：2026-10-20。依据现行179页需求文档UC-25“开立处方并衔接院内外取药”。本批完成院外处方；院内审方、实际发药及库存收费联动仍待实现，未将UC-25标为全部完成。需求PDF、LaTeX、核心模型及原设计SQL均未修改。

## 已接入的业务

1. **核实药品目录**：在现有材料目录明确“处方药品”分类，由负责人核实名称、规格、基本单位和精度后启用。既有目录补充药品分类时保留原库存及流水，重新交负责人确认；普通耗材不能直接作为处方药品选择。
2. **建立或修订草稿**：牙医从本人或明确交接的就诊进入处方页面，明确诊断、药品及规格、数量、用法用量、必要疗程说明和注意事项。系统不生成药物选择或推荐剂量。
3. **确认开立**：先记录本次病历诊断，完成健康资料复核，再明确核对患者、病史、过敏、既往用药及整张处方。核对期间患者、病历或药品资料发生变化时，要求重新核实。
4. **交付院外处方**：保存患者号、姓名、医师、开立时间及正文快照，提供受保护的HTML处方副本，可用浏览器打印。副本显示生成时间和生成时状态；适用签章仍由医师按机构要求办理，不宣称已接入专业电子签名平台。
5. **差错处理**：已开立正文和药品明细冻结；核实后作废，保留原方及作废依据。需要更正开方时另建新处方，不覆盖或重新启用旧方。

院外取药不创建诊所发药、不扣药品库存，也不因开方生成诊所药费。助理、前台、收费人员及负责人岗位不能查阅或开立处方；负责人切换到牙医岗位后仍受本人及明确交接的就诊范围限制。

## 与文档中类和表的对应

| 文档对象 | 本批代码与数据库落实 |
|---|---|
| 处方 | `prescription`，保留患者、就诊、开立人、取药路径、状态、审核状态及开立时刻；补充诊断、用药指导、健康复核来源和开立快照 |
| 处方明细 | `prescription_item`，关联既有`material`，保留开立时药品名称规格、用法、基本单位、整数缩放数量及数量精度 |
| 材料 | 复用既有目录与负责人核对流程，增加`is_drug`区分药品和普通材料，不单独复制一套药品主表 |
| 健康复核与病历 | 引用既有`health_review`、`clinical_record`，开立前核对最新健康资料与当前病历版本 |
| 实际发药 | `dispense_record`及其库存收费联动留待院内流程实施，本批未创建假发药记录或虚构资质 |

处方和药品明细开立后由数据库触发器及正文摘要共同保护。药品单位、精度和分类被处方引用后不能改写；药品停用不覆盖历史处方内容。

## 本地数据升级

- 运行库版本：`20261020`，物理表由88增加至90，只新增文档中已有的处方、处方明细两张业务表。
- 已识别的旧库升级前自动生成SQLite一致性备份；未知结构仍拒绝打开。升级失败会回滚本批结构和权限变更。
- 本地升级前后按旧列核对全部88张原表的记录摘要，原记录保持不变。仅新增两项处方权限及其牙医岗位关联；原材料分类默认为普通材料，不擅自认定既有药品。
- 原备份已按同一组旧表摘要核对，外键检查通过，数据库完整性为`ok`。本批没有向运行库添加演示处方。

## 验收

- **255项自动化检查通过，0失败**：新版198项、旧版兼容57项，本批新增14项。
- 专项检查覆盖：药品分类与重新确认、健康及诊断前置条件、患者和病历并发版本、处方冻结与作废、重复提交、权限隔离、审计失败回滚、受保护导出和旧库升级回滚。
- 网页演示覆盖：助理登记虚构药品、负责人核对分类、牙医建立草稿、两位数量精度、缺少健康复核时拒绝开立、草稿修订、确认后响应丢失按原提交核实、导出可打印副本、作废留痕及手机宽度。
- 临床、收费、诊椅设备、复诊随访、材料库存、影像文书六组既有网页回归通过。业务演示采用隔离内存库，药品和用法均为流程占位，不用于实际治疗。
- 本地3001服务已加载当前版本。新增页面、静态资源、备份、原数据及需求文件摘要已核对。
